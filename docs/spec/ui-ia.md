## 背景

在已定 v1 决策内设计（不推翻）：MCP-first；Flutter 3.47.7 桌面；macOS 26 arm64；UI 默认中文；菜单栏常驻 + Dock；资源全部可见可管理，app 创建的资源打 `com.ghost233.*` label 仅作标记；v1 范围 = containers 全操作（list/create/start/stop/restart/delete/logs/exec）+ images（list/pull/delete/inspect）+ system 状态与启停 + mounts/networks 只读 + Compose up/down。Cmd+K、Builds、Networks 写 → v2。

调研报告对本简报的直接输入：

- 桥接（#7）：日志经 XPC FileHandle 流式推送（支持跟随）；stats 只有快照轮询（orchard 模式：可见 2s / 不可见 10s）；镜像 pull 有进度回调（~10Hz，可折叠为进度条）；`system start` 可能触发内核安装，耗时长且必须显式传 flag → UI 需要「正在安装内核」的进行中态。
- compose（#6）：只有 up/down；桥接层内嵌 planner 可给出逐 key 严重级别 → Compose 页可展示「将忽略/拒绝什么」。
- MCP（#4）：`mcp_dart`，stdio + 仅 127.0.0.1 HTTP，端口可配 → 设置需要 MCP 区块（开关/形态/端口/连接信息）。
- 系统要求（#11）：检测命令齐全（version/status --format json、内核符号链接）；分发非沙盒 → 无沙盒约束影响 UI；onboarding 流程由 #9 负责，本简报只定入口位置。

视觉基线遵循 macos-ui-standards：字体角色（标题 Title 1/2/3、正文 13pt）、语义色、侧栏 224（200–280）、表行高 40/56、控件八状态、空/加载/内容/失败四态必备。

## 候选方案与权衡

### D1 主窗口导航结构

| 方案 | 结构 | 优点 | 缺点 |
|---|---|---|---|
| **A 三列工作台**（原型 variant=a） | 侧栏分节（容器/Compose/镜像/挂载/网络 + 运行时 + 设置/MCP），列表 + 右侧检查器，详情独立标签页 | macOS 惯例（访达/App Store 式）；与 orchard 心智一致，迁移成本低；检查器满足「瞥一眼」；v2 加 Builds/Networks 写只需加侧栏项 | 侧栏 7+ 项略长；检查器与详情页信息重复维护 |
| **B 资源总列表**（variant=b） | 窄图标栏 + 单一「资源」列表混合全部类型，类型筛选 chips，全屏详情 | 「资源全部可见」最彻底；入口极简 | 混合列表列定义难以统一（容器要 CPU/端口，镜像要大小/架构）；批量操作与类型特有操作呈现别扭；偏离 macOS 惯例 |
| **C 顶部导航 + 仪表盘**（variant=c） | 顶部分段控件，首页为状态仪表盘卡片 | 首屏信息密度高，系统状态一目了然；对「打开 app 看健康度」的场景友好 | macOS 桌面罕见顶部主导航（更像 iOS/web）；仪表盘是第 8 个需要维护的页面；分段控件超过 5 项就放不下 |

**推荐 A**。补充：C 的仪表盘价值可用更轻的方式获得——系统状态放侧栏底部指示 + 工具栏状态 pill，不必单设页面。

#13 回填附注（不推翻 D1）：侧栏「管理」节新增第 8 项「项目」（位于「容器」之后），正好落在 A 方案「v2 扩展只加侧栏项」的预判路径上；侧栏项总数变为 9（容器/项目/Compose 项目/镜像/挂载/网络 + 运行时 + 设置/MCP）。

### D2 容器详情页形态

| 方案 | 结构 | 优点 | 缺点 |
|---|---|---|---|
| **A1 标签页**（原型已演示） | 概览 / 日志 / 终端 三个标签页 + 顶部操作栏 | 日志与终端拿到全内容区（都是高频大空间需求）；结构清晰，v2 可加「统计图」标签 | 无法同时看日志和概览 |
| A2 单页分段滚动 | 所有信息一屏滚动，日志/终端为内嵌区块 | 无导航成本 | 日志流与终端在滚动页内高度受限，体验差 |
| A3 概览 + 底部面板 | 上概览、下可拖分隔的日志/终端面板 | 日志与概览同屏 | 实现复杂度高；小窗口下两区都局促 |

**推荐 A1**。理由：日志（流式、需筛选/导出）和 exec 终端是重交互区，值得全宽全高；概览是只读速览，不需要与日志同屏。

### D3 日志与 exec 终端呈现

- 日志：详情页标签页内嵌（等宽字体、跟随/暂停、筛选、导出；数据源 XPC FileHandle 流）。**可选增强：「在新窗口打开日志」**，方便对照多个容器——推荐 v1 就做，成本低（窗口复用同一日志组件）。
- exec 终端：详情页标签页内嵌，单会话；多会话/独立窗口 → v2。
- 菜单栏与列表行的「日志」快捷入口 = 打开主窗口并定位到该容器日志标签页。

### D4 菜单栏常驻项深度

| 方案 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| **M1 中等深度**（原型已演示） | 状态行（运行时+版本）→ 运行中容器列表（最多 5 个 + 「查看全部」），每项悬停出「停止」→ 启停运行时 → 打开主窗口 / MCP 配置 / 设置 / 退出 | 覆盖 80% 快速操作；层级只有 2 层 | 容器很多时截断 |
| M0 极简 | 仅状态 + 启停运行时 + 打开主窗口 | 实现最少 | 快速操作价值丧失 |
| M2 深菜单 | 容器分组子菜单（含 start/stop/logs/restart）、镜像与 Compose 区块 | 功能全 | 菜单臃肿，macOS 菜单栏不适合深度管理 |

**推荐 M1**。图标用 `▣n` 形态（运行中容器数），运行时停止时图标变灰。

### D5 首页与默认页

- 选项：**默认页 = 容器列表**（推荐）——管理工具的核心对象即首页，无额外维护成本。
- 选项：独立「概览」仪表盘页（方案 C）——不推荐，见 D1。
- 系统状态露出：工具栏右侧状态 pill（运行时状态 + container 版本），点击进入「运行时」页。

### D6 Compose 呈现

- 选项：**独立侧栏项「Compose 项目」**（推荐）：项目列表（名称/服务数/运行中数/compose 文件路径）→ 项目详情 = 服务容器表格 + up/down + planner 报告的「将忽略/拒绝的配置项」列表（行号+严重级别，#6 调研直接支持）。
- 选项：仅在容器列表按 label 分组——作为补充保留：容器列表提供「按项目分组」开关（原型工具栏已示意）。
- 项目来源：v1 无「导入 compose 文件」流程，项目通过插件执行过 up 后由 label 聚合发现；「打开 compose.yml」入口指向 Finder/编辑器。

### D7 挂载与网络（只读）呈现

- 选项：**独立侧栏只读页**（推荐）：挂载 = 跨容器聚合表（主机路径 → 容器:容器内路径、读写）；网络 = 表（名称/子网/DNS 域/容器数），行展开看成员容器。只读页也遵循空/加载/失败四态。
- 选项：并入容器详情的「挂载/网络」区块——已在详情概览里存在，聚合页解决的是「跨容器视角」。
- 两个只读页不放任何写操作按钮，避免暗示可写（写 → v2）。

### D8 空态、错误态与 onboarding 入口

- **四态模板统一**（macos-ui-standards 页面模板）：空态 = 图标 + 一句话 + 直接主操作（如「新建容器」「拉取镜像」）；失败 = 错误说明 + 「重试」+ 详情展开。
- **运行时未启动**是全局态：所有数据页显示统一的「运行时未启动」占位（原型 state-error 已演示），提供「启动运行时」主按钮 +「打开引导检查」次按钮；启动过程显示进行中（含「正在安装内核…」阶段，对应 #7 的 kernel-install 事实）。
- **版本不匹配**（< 1.6.0）：全局横幅（非模态），指向 onboarding 的升级路径。
- **onboarding 入口**（流程本身归 #9）：①首次启动自动进入；②「运行时」页常驻「重新运行引导检查」；③全局异常态（未安装/版本低/未启动）的「打开引导检查」按钮。入口文案统一为「引导检查」。
- 系统页命名推荐「运行时」（对应 `container system`），页内：状态卡片、启停按钮（停止需确认，列出运行中容器数）、版本（client/server 双端）、安装路径、内核状态。

### D9 设置页内容（MCP 是重点）

- **MCP 服务**：开关、形态（stdio / HTTP 127.0.0.1 / 两者）、端口（默认建议 8810，占用时提示换端口）、连接信息卡片（一键复制 Claude/Codex 配置片段）、最近 MCP 调用简表（MCP-first 差异化：让用户看见 agent 在做什么）。
- **通用**：菜单栏图标显示开关、默认启动页、语言（v1 仅中文，留占位禁用态）。
- **Container**：二进制路径（自动检测 /usr/local/bin、/opt/homebrew/bin，可自定义覆盖）、版本显示。
- **关于**：版本、许可（参考 orchard MIT 的致谢）。

### D10 新建容器表单

- 选项：**单 sheet 分段表单**（推荐）：镜像（**本地镜像下拉**；镜像须已存在，缺失时引导先去镜像页拉取——2026-10-24 拍板，create 不自动 pull）、名称、端口发布、挂载、环境变量、标签（资源限制 CPU/内存延 v2，T3 审查 P1 裁决）；「高级」折叠（DNS、启动命令）。宽 480–640，分段标题 Title 3。
- 选项：多步向导——步骤间耦合低、参数间有引用（挂载依赖已选镜像），单页滚动更顺。
- 危险操作确认：删除容器/镜像、停止运行时、compose down 使用确认对话框（480 宽，说明影响面，如「该容器有 2 个挂载」）。

### D11 项目页（#13 回填 · 决策已定）

> 依据 issue #13 决策与 docs/research/container-build-registry.md 的磁盘/GC 事实，并经 2026-10-23 用户 grilling 终轮拍板修订。项目 = label 约定 `com.ghost233.project=<name>` + 镜像自由命名 `{prefix}-{自定义名}`（如 `myapp-go1`；同名构建默认替换，无 replace 交互）+ 可选 `ghostcontainer.toml`。Builds 以项目工作流承载的最小形态进 v1（Dockerfile build + tag；无独立构建页；构建日志进项目详情，见下）。

**项目列表页**（侧栏「管理」节第 2 项「项目」）：

- 列：名称（副行显示 label，「本应用创建」标记）/ 镜像数 / 运行中容器数 / 磁盘占用 / 最近构建时间。
- 工具栏：搜索 + 「⟳ 刷新磁盘快照」+ 主操作「＋ 从目录新建项目…」（读 ghostcontainer.toml 初始化）。
- 行点击 → 项目详情（全页覆盖层，复用容器详情的导航心智）。
- 空态：图标 + 一句话 + 「＋ 从目录新建项目…」；错误态遵循 D8 全局运行时态。
- 磁盘占用列 = **内存快照 + 用户手动刷新**：不做进页自动校准、不做任何实时刷新（终轮拍板）；总量校准数据源为 `container system df --format json`，事实以 CLI 结果为准。

**项目详情**（分区块卡片 + 底部构建日志面板共存，终轮拍板定稿、不分版本过渡）：

1. 标题栏：返回 + 项目名 + label；操作组：**构建新版本**（Dockerfile build；同名默认替换）、**推送到本地 registry**、**一键回收…**（destructive）。
2. 镜像列表卡片：列 = 名称 / 大小 / 创建时间 / 徽标（使用中/未使用 × 已推送 registry/仅本地），按创建时间倒序；「未使用且已推送」行内操作「删除本地副本…」（三选弹窗，见下）。卡片头部右侧提供「查看上次失败日志」入口（失败/取消的构建日志落盘：尾部 1000 行 + 元数据、保留 20 条、仅失败/取消落盘）。
3. 成员容器表：复用容器列表行形态（状态点/名称/镜像/端口/时长 + 行内停止/日志/启动/删除）。
4. 回收报告卡片（上次一键回收结果）：大数字「已释放 X」+ 逐项清单（删除项与跳过项及原因）+ 时间与执行链路注记（container prune → image delete → image prune）。底部注记层级共享语义：删 tag 只释放独占层，最后一个引用删除 + GC 后才真正回收磁盘（container-build-registry §4.3）。
5. **底部构建日志面板**（可展开/折叠，与卡片区块共存）：构建进行中显示 `--progress plain` 流（Service 层 100ms ≈10Hz 合并节流，architecture.md §5.3；窗口内中间行被合并、末行必达），标题栏含目标镜像名与状态（进行中/成功/失败/已取消）；「构建新版本」点击后面板展开进入进行中态；「查看上次失败日志」打开面板呈现最近一次失败记录。

**registry 不设状态区**（终轮拍板）：本地 registry 是全局唯一单例、无特殊意义、不需要特殊处理——registry 容器在容器列表自然可见即可。循环依赖风险提示（推送后删本地镜像的恢复依赖 registry 容器与数据卷存活）保留在「删除本地副本」与「推送到本地 registry」的确认文案里，不设常驻区块。

**「删除本地副本」三选确认弹窗**（480 宽，终轮拍板）：文案含循环依赖提示；三个动作 = **取消 / 仅删除 / 归档并删除**（先推送到本地 registry 再删本地副本）。

**一键回收确认弹窗**（480 宽对话框，语义不变）：

- 销毁清单分组列出「将删除」与「将跳过」（跳过项注明外部引用原因）；注明「事实以 CLI 结果为准，完成后显示回收报告」。
- **force 复选框默认勾选**（项目自动化回收分叉）；说明文案点出与手动单删镜像「默认不勾选」的差异。
- 确认钮为红色主按钮「回收并显示报告」。

## 我的推荐汇总

D1=A（三列工作台）、D2=A1（标签页详情）、D3=内嵌标签页+日志可弹新窗口、D4=M1（中等深度菜单栏）、D5=默认页容器列表、D6=独立 Compose 侧栏项+容器列表分组开关、D7=独立只读聚合页、D8=统一四态模板+全局运行时态+「引导检查」入口三处、D9=设置含 MCP 区块、D10=单 sheet 分段表单。D11 项目页按 #13 已定决策执行，不在待拍板清单内。

整体心智：**侧栏 = 资源类型，工具栏 = 状态与主操作，检查器 = 速览与快捷操作，详情页 = 深度操作（日志/终端），菜单栏 = 状态 + 高频启停**。
