# 目录与 MCP 管理：讨论记录

本文记录当前讨论中确认的方向与尚待细化的问题；现有规格和实现尚未因此自动更新，也不表示功能已完成。

## 已确认

- MCP 是目录使用容器管理能力的统一入口，底层仍使用 Docker 兼容运行时；项目侧禁止直接调用 Docker 命令的软限制由用户自行处理。本阶段只考虑一个本地运行时，不考虑或兼容跨网访问。
- 每个客户端可独立接入同一个本机 MCP 服务。目录级操作每次传入本地绝对路径，通常是 Git 仓库根目录；解析后指向同一目录的符号链接路径视为同一目录。分别选定的父子目录独立。目录限定资源管理范围，但不是安全隔离边界。
- 创建、构建或显式绑定资源时可自动登记目录；仅查询未登记目录返回空结果，不自动登记。界面可展示全部普通资源，但目录视角不要求展示未登记资源。已有普通容器或镜像可通过 MCP 显式登记，不依据名称或路径自动接管。
- 目录容器按目录管理，不同目录默认不共享同一容器；不同目录可使用相同业务名称，系统负责避免实际名称冲突。支持标准 Compose；同一目录可有多个 Compose 项目并分别操作，目录级清理需明确指定。
- 登记镜像由调用方选择一个主要分类：`base` 是全局基础镜像，`sdk` 是按目录显式绑定、可共享的 SDK 镜像，`dev` 是目录专属镜像，`svc` 是可共享的现成服务镜像，例如 MySQL。分类不是 Docker 版本 tag，普通未登记镜像不强制分类。各类镜像不必严格逐层构建；镜像可直接用于创建目录容器。目录可创建 SDK 镜像供其他目录按需绑定，SDK 版本切换由各目录明确决定。分类可显式变更，但须检查绑定及引用，不满足新规则则拒绝。
- 目录视图展示所属容器、专属镜像及绑定或引用的共享镜像，并标识类别。全局共享基础镜像单独展示；有产品分类标记但失去预期目录关系的资源进入界面的「未关联」分组，供检查，不自动删除或归属。产品创建或登记的资源应保留可识别的产品标记及适用分类；对于不能原地加标的已有资源，允许只保存在应用登记数据中，数据丢失后可能无法自动发现。
- 目录批量清理须预览、调用方明确确认、执行前重检。持久数据卷默认保留，仅明确指定时才考虑删除；共享 SDK 镜像仍被任何目录绑定或容器引用时不可列为清理候选。目录清理保留公共镜像并解除目录引用；顶层公共镜像保留。目录专属镜像仅在没有任何容器引用且调用方确认后删除；否则保留并报告原因。
- 旧版本未正式启用，不要求迁移旧项目数据。目录搬迁后不迁移归属，在新目录重新构建；旧目录及资源不自动处理，先保留。

## 与既有记录的关系

- [Issue #13](https://github.com/Ghost233/GhostContainerManager/issues/13) 后续决策依赖项目名、`prefix` 和 `project|path`，与目录替代产品项目的决定冲突，需要后续更新规格和接口；旧版本无需迁移。
- [Issue #15](https://github.com/Ghost233/GhostContainerManager/issues/15) 和 [Issue #20](https://github.com/Ghost233/GhostContainerManager/issues/20) 的全部资源可见与目录限定需要区分：用户澄清全局可见不等于目录视角管理全部资源。既有具体全局操作契约需进一步核对，不能直接推断其保留或移除。
- [Issue #21](https://github.com/Ghost233/GhostContainerManager/issues/21) 已涉及 Compose；本次保留 Compose 并增加目录归属约束。[Issue #28](https://github.com/Ghost233/GhostContainerManager/issues/28) 的目标限定、预览和重检及共享资源保护应保留。
- [Issue #37](https://github.com/Ghost233/GhostContainerManager/issues/37) 的运行时数据目录不是本次所说的管理目录，不应混为一谈。
- [ADR 0002](adr/0002-dispatch-schema-validation.md) 保留分发前校验原则，但其中 `project/path` 业务校验示例将与新目录契约冲突，实施时需修订；其他已有 MCP 注册表、风险注解和分页 ADR 不因本次讨论自动废弃。

## 尚待细化

- 现有外部资源显式登记、分类变更及未关联资源重新关联的具体流程与冲突处理。
- Compose 创建的网络、卷等资源的归属、共享与删除边界；现有全局工具与目录级工具的具体接口划分。
- MCP 工具名称及参数、旧规格和相关 issue 如何更新，以及实际实现、验证与交付范围。
