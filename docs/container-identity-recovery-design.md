# 管理目录容器身份与创建恢复：实施设计

本文是 #48 的实施设计，不表示目录容器能力已实现。目录是防误操作范围，不是对恶意客户端的安全边界；本设计只针对一个本地 Docker 兼容运行时。MCP 和界面应复用共享管理入口，不通过名称猜测归属或自动接管普通资源。

## 当前缺口

- 创建桥接接口只返回成功或失败，丢弃运行时返回的容器 ID；现有容器快照优先使用名称。名称可复用，不能证明原容器仍存在。
- 目录登记当前仅保存规范路径和字符串列表，尚未与容器创建、查询或生命周期操作接通。登记文件的原子替换不构成与运行时创建之间的事务。
- 创建成功后的刷新或启动失败已有部分失败信息，但调用超时、进程中断或返回结果丢失时，调用方无法知道运行时是否已经创建容器。按名称盲目重试或删除可能误操作。

## 身份与范围

1. 管理目录仍以现有规范绝对路径规则识别：符号链接别名归一、分别选择的父子目录独立。旧路径重建后的身份仍未决，不在本设计中自动迁移或清理旧资源。
2. 将业务名称、实际运行时名称和运行时完整容器 ID 分开。实际名称由系统生成以避免跨目录冲突；名称冲突必须作为冲突处理，不按名称接管容器。目录内业务名称冲突的具体语义需在实施契约中明确。
3. 成功创建后保存运行时返回的完整 ID；目录操作使用已登记 ID 并在执行前核对运行时实际对象。被删除后出现同名新容器时，旧登记不能转移给新容器。普通未登记资源不因名称、路径或标签相似而自动接管。
4. 应用创建的容器携带产品标记及随机、唯一的创建操作标识，供恢复时关联；用户不能通过创建参数覆盖保留标记。标记仅用于一致性核对，不是认证凭据，也不能单凭标记授权接管或删除。
5. 目录与 ID 的归属登记要有唯一性和并发控制；同一容器不能被两个管理目录静默登记。显式登记已有普通资源的冲突规则属于 #45，不由创建恢复流程代替。

## 创建与恢复协议

在触发运行时副作用之前，持久化包含规范目录、业务名称、预选实际名称、唯一操作标识及阶段的创建意图；不保存密钥或不必要的环境变量。意图持久化失败时不得调用运行时。对同一意图的并发恢复与完成操作须串行化，且登记和阶段推进须能安全重复。

| 阶段或观察 | 处理 |
| --- | --- |
| 意图已保存，尚未确认创建 | 以操作标识查询运行时并检查完整 ID、产品标记和预期名称；不得仅按名称推断。若运行时不可达，保持待核对并报告结果未知，不盲目重试。 |
| 查到唯一匹配的本次创建 | 以完整 ID 原子登记归属，再推进意图；重复恢复不得产生重复归属。 |
| 无匹配 | 只有查询覆盖完整运行时且已确认原创建请求不再运行时，才可安全地标记未创建并允许明确重试；否则继续保持未知。不得仅因一次查询为空就断定失败。 |
| 多个匹配、标记不一致或登记冲突 | 停止自动恢复，保留资源和记录并报告冲突；不自动删除或接管。 |
| 已创建但登记失败 | 保留容器与创建意图，返回可核对的操作标识和已知 ID；修复存储后可重复恢复登记。不得将操作报告为完整成功。 |
| 已登记但启动或刷新失败 | 保留归属和容器，返回已创建、ID、失败阶段和可重试动作；恢复时按 ID 重新检查状态，不重新创建或自动删除。 |
| 进程重启或客户端断连 | 未完成意图仍可查询并恢复；客户端断连不隐含删除。恢复不能把不能证明的结果变成成功。 |

运行时创建返回完整 ID 后，登记前仍可能崩溃；故运行时标记与持久意图都不可省略。若底层无法证明异步创建已经终止，即使暂未发现匹配项也应保持未知，避免重复创建。登记库损坏、不可读或运行时不可信时应失败关闭，不能当成空登记库。

## 分步交付与依赖

- **A：可靠创建身份与恢复（#48 的前置设计）**：打通创建返回完整 ID、持久意图、标记核对、归属登记及失败恢复；保持现有全局调用兼容，直到调用方明确迁移。验证持久意图后崩溃、创建后响应丢失、登记写入失败、重启恢复及启动/刷新失败。
- **B：目录创建、启动和查询（#48）**：基于 A 在共享入口完成目录范围内创建、启动和查询，验证同名跨目录、符号链接、父子目录、并发和同名替换。仅查询未登记目录不产生登记；不接管普通容器。
- **C：MCP 目录入口（#49）** 和 **目录展示（#50）**：依赖 B 暴露和展示同一份归属；沿用注册表校验、风险标注及分页契约。既有全局工具保留或修改不在此文擅自决定。
- **后续生命周期（#43）**：复用可靠 ID 和目录归属，在每次有副作用的操作前重检目标；目录清理及已有资源接管分别由 #46、#45 处理。

A 与 B 是可验证的实施顺序，不代表可以绕过现有工单审批或宣称 #48 已完成。实现涉及 bridge 返回契约、容器服务与登记职责及调用者，不能作为只修改单个模块的局部修补。

## 最低验证矩阵

自动化覆盖：同一业务名跨目录、同目录并发、父子目录与符号链接别名、相同名称替换容器、保留标签冲突、登记唯一性、存储损坏及写入失败；注入运行时已创建但响应丢失、查询不可达、零/多匹配、进程重启、重复恢复、启动或刷新失败。断言未登记和其他目录的资源不被修改或删除，未知状态不会被错误报告为成功。

集成验证使用隔离的本地 Docker 兼容运行时，覆盖创建、归属查询、启动、重启恢复及同名替换；记录运行时版本、测试前后资源及真实退出状态，不操作用户已有资源。尚未实施或验证时，不将上述设计称为已交付功能。
