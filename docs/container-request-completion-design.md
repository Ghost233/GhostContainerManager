# 容器请求终止确认：设计提案

状态：**提案，尚未实现或验证**。本设计服务于 [#61](https://github.com/Ghost233/GhostContainerManager/issues/61) 的创建与重启恢复；它不解除 [PR #58](https://github.com/Ghost233/GhostContainerManager/pull/58) 的草稿限制，也不改变现有运行时行为。

## 问题和目标

创建或启动容器是对 Docker 兼容端点的外部副作用。客户端超时、退出或丢失响应后，原请求可能仍在引擎中执行；应用重启后也是如此。即便一次完整查询返回零个或唯一匹配，也不能证明稍后不会出现另一个副作用。终止确认的目标是：**只在有可靠证据表明原请求不再执行、其副作用已可供后续核对时，允许恢复流程继续；否则持续待核对。** 安全优先于自动恢复的可用性。

## 提议的接缝

恢复编排依赖一个请求执行模块，而不是自己推断 CLI 进程状态。它针对不可变的端点身份、操作 ID、操作类型及请求内容摘要提供两项能力：提交一次操作，以及在重启后查询同一操作的证据。端点身份应由适配器建立并持久记录，不能仅凭可变的 context 名称或 socket 路径认定相同引擎。查询结果仅有：

- **未确认**：可能未提交、正在执行、结果丢失，或者证据不可用、不完整、不可信；不得据此重试或接管。
- **已终止**：有权威执行方提供与记录的端点、操作 ID 和请求内容匹配的持久证据，保证原请求不会再产生副作用，且终止前的副作用在后续核对中可见。结果可包含成功、明确失败或副作用仍需核对；终止本身不等于成功。

请求 ID 不能跨端点、不同请求内容或不同执行尝试复用。终止证据必须绑定精确的操作与端点，具备防止误关联的完整性保证；标记只用于一致性检查，不是授权或所有权证明。查询失败、端点变化、记录损坏或证据无法验证，一律返回未确认。启动请求也需要相同语义，不能把观察到运行中或停止当成请求已经结束。

### 适配器的可行性条件

能够提供上述保证的适配器需要权威执行方支持持久操作记录和查询，并规定重复提交的去重、终态发布与副作用可见性的顺序；即使执行方重启，也不能把未完成的操作误报为终止。记录写入与实际执行之间的崩溃窗口必须有明确的恢复协议，不能单靠客户端日志或一个独立包装进程假设原子性。具体运行时、协议、存储持久性及可见性保证尚待验证，不能仅凭本提案视为存在这种适配器。

现有 Docker CLI 接缝没有已验证的、可跨应用重启查询的请求终止证据。CLI 被杀死、连接关闭、等待一段时间、事件流、容器名称唯一或查询快照都不足以证明引擎已停止处理。客户端持久化意图、标签和完整 ID 可以辅助核对，但不能替代终止证据。**默认适配器对响应丢失或崩溃后无法证明终止的操作返回未确认，不启用自动消解。** 直接收到完整响应的路径可按其实际响应契约继续处理；如果在结果持久化前崩溃，重启后仍须依据持久证据判断，不能假设已收到响应。

## 恢复规则

1. 副作用之前，持久保存操作 ID、端点身份、请求内容摘要、管理目录、业务名称、实际名称和阶段；在存储失败时不发送请求。同一操作的提交和恢复必须互斥。不同操作 ID 之间还须以持久、跨进程原子保留的资源键互斥：创建按端点、管理目录和业务名称，启动按端点和完整容器 ID；未确认的操作继续保留其键，不允许新尝试绕过。锁定或保留不可验证、冲突或存储失败时失败关闭。归属唯一性另行检查，不能由此锁替代。持久性范围应在实现中明确并验证，不能默认为断电安全。
2. 如果没有可验证的终止证据，保留待核对记录和已知完整 ID；不重复创建、启动、自动登记或删除。可报告未确认状态，但人工处置也必须避免声称旧请求已终止。
3. 确认终止后，针对**记录的同一端点**重新查询并检查完整 ID、实际名称、产品标记、操作 ID 和目录登记冲突。完整查询仍不是所有权证明；多个匹配、替换、查询不完整或登记冲突均保持待核对。只有满足既定登记契约的唯一身份才能进入登记流程。
4. 零匹配仅在已确认终止且查询完整时说明该次查询未发现匹配，不自动授权重试或删除：还须按操作结果、资源生命周期和产品策略判断。登记后启动也要使用自己的操作记录和终止证据。失败或未知结果保留归属与可恢复信息。

以上是接口契约，不要求对现有公开调用方立即变更。实现前须确定执行方是否真的提供该契约，并单独评估运行时桥接、持久登记和共享管理入口的协调变更；若没有这种能力，保守待核对是有效结果，不应虚构自动恢复。

## 实施前验证清单

- 针对候选执行方证明终止证据在响应丢失、客户端崩溃、执行方重启及存储崩溃各窗口的含义；证明终态后不会出现迟到副作用，且后续查询可见。区分进程重启与断电保证。
- 测试提交前后、执行中、终态发布前后和登记前后的崩溃；并发提交/恢复、重复查询、操作 ID 与请求摘要冲突、端点更换、损坏或过期证据均不得产生重复副作用或错误归属。
- 覆盖创建和启动的成功、明确失败、未知结果，以及零／一／多个匹配、同名替换、查询不完整、登记冲突和不可达端点。对无法确认的每条路径断言不重试、不接管、不删除。
- 用真实、适用的 Docker 兼容端点测试真实在途请求而非仅注入假响应；记录版本、故障注入方式、测试资源范围和退出状态。若端点不提供必要能力，记录该限制，不将模拟适配器测试当成真实终止证明。
